# Anthropic Messages API Compatibility — ZEAZ Gateway

This document describes the Anthropic Messages API compatibility of the ZEAZ Gateway Provider.

## Supported Endpoints

| Endpoint | Method | Status | Notes |
|----------|--------|--------|-------|
| `POST /v1/messages` | POST | Supported | Non-streaming and streaming |
| `GET /v1/models` | GET | Supported | Requires authentication |
| `GET /health/live` | GET | Supported | No authentication |
| `GET /health/ready` | GET | Supported | No authentication |

## Request Compatibility

| Parameter | Status | Notes |
|-----------|--------|-------|
| `model` | Supported | Route alias (e.g., `zeaz-claude`) |
| `max_tokens` | Supported | Validated 1 to `max_output_tokens` |
| `messages` | Supported | Array of role/content objects |
| `system` | Supported | Passed through to Ollama |
| `metadata` | Partial | Accepted but not acted on |
| `temperature` | Supported | Range 0.0–2.0 |
| `top_p` | Supported | Range 0.0–1.0 |
| `stop_sequences` | Partial | Accepted in request |
| `stream` | Supported | Server-Sent Events |
| `tools` | Partial | Passed through as text |
| `tool_choice` | Partial | Accepted in request |

## Response Compatibility

| Field | Status | Notes |
|-------|--------|-------|
| `id` | Supported | Generated by gateway |
| `type` | Supported | Always `"message"` |
| `role` | Supported | Always `"assistant"` |
| `model` | Supported | Route alias echoed back |
| `content` | Supported | Array of text blocks |
| `stop_reason` | Supported | `"end_turn"`, `"max_tokens"`, `"stop"` |
| `stop_sequence` | Supported | `null` when not applicable |
| `usage` | Supported | `input_tokens`, `output_tokens` |
| `usage.input_tokens` | Supported | From provider response |
| `usage.output_tokens` | Supported | From provider response |

## HTTP Behavior

| Behavior | Status |
|----------|--------|
| `anthropic-version` header | Accepted, not validated |
| `content-type: application/json` | Required |
| `Authorization: Bearer` | Required for `/v1/messages` |
| `x-api-key` | Supported as alternative |
| Invalid credentials | HTTP 401 |
| Malformed JSON | HTTP 400 |
| Missing required fields | HTTP 400 |
| Invalid model alias | HTTP 404 |
| Rate limiting | HTTP 429 |
| Upstream errors | HTTP 502 |

## Streaming (SSE)

| Event | Status |
|-------|--------|
| `message_start` | Supported |
| `content_block_start` | Supported |
| `content_block_delta` | Supported |
| `content_block_stop` | Supported |
| `message_delta` | Supported |
| `message_stop` | Supported |
| Error events | Supported |
| Connection termination | Supported |

## System Prompts

| Feature | Status |
|---------|--------|
| String system prompts | Supported |
| Structured system blocks | Partial |
| System prompt ordering | Preserved |
| System prompt preservation | Passed to provider |
| Token accounting | From provider response |

## Local-Only Enforcement

The `zeaz-claude` route is configured with `cost_policy: LOCAL_ONLY`:

- Routes only to Ollama (`cost_class: FREE_LOCAL`)
- No fallback to OpenRouter, Gemini, Groq, or Anthropic Cloud
- If Ollama is unavailable, returns HTTP 410 (fail closed)
- Applies to both `execute()` and `stream()` paths

## Limitations

- Tool calls are passed through as text content, not structured `tool_use` blocks
- `tool_choice` is accepted but not enforced
- `metadata` is accepted but not stored
- `stop_sequences` is accepted but may not be enforced by all providers
