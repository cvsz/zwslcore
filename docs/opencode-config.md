# OpenCode Configuration for ZEAZ Gateway

OpenCode v2.2.2 is installed at `/home/cvsz/.opencode/bin/opencode`. This document describes how to configure OpenCode to use the ZEAZ Gateway as an Anthropic-compatible provider.

## Provider Configuration

OpenCode stores provider configurations in `/home/cvsz/.config/opencode/`. Add a custom provider for the ZEAZ Gateway:

```json
{
  "zeaz-gateway": {
    "canonical": "zeaz",
    "name": "ZEAZ Gateway",
    "package": "aisdk:@ai-sdk/openai-compatible",
    "settings": {
      "baseURL": "http://localhost:8080/v1"
    },
    "headers": {
      "Authorization": "Bearer ${PROVIDER_CLIENT_KEY}"
    },
    "models": {
      "zeaz-claude": {}
    }
  }
}
```

## Environment Variables

Set the following in your shell environment before launching OpenCode:

```bash
export PROVIDER_CLIENT_KEY="<your-provider-client-key>"
export ANTHROPIC_BASE_URL="http://localhost:8080"
export ANTHROPIC_AUTH_TOKEN="$PROVIDER_CLIENT_KEY"
export ANTHROPIC_MODEL="zeaz-claude"
```

Never hardcode `PROVIDER_CLIENT_KEY` in configuration files. Use environment variable substitution or OpenCode's credential store.

## Launch Command

```bash
/home/cvsz/.opencode/bin/opencode
```

## Verification

After configuration, verify that OpenCode routes through ZEAZ Gateway:

1. Start OpenCode
2. Select the `zeaz-claude` model
3. Send a test message
4. Confirm the response is generated by the local Qwen model (not Anthropic Cloud)

## Model Selection

The `zeaz-claude` route maps to Ollama running `qwen2.5-coder:3b` with `cost_policy: LOCAL_ONLY`. This means:

- Requests are routed only to Ollama (FREE_LOCAL provider)
- No fallback to OpenRouter, Gemini, Groq, or Anthropic Cloud
- If Ollama is unavailable, the gateway returns HTTP 410 (fail closed)

## Security Notes

- `PROVIDER_CLIENT_KEY` must never be stored in plaintext in configuration files
- The gateway authenticates all `/v1/messages` requests
- TLS verification is enabled for HTTPS connections
- Ollama is not exposed to the public Internet
